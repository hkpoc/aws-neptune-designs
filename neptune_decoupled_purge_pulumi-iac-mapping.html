Neptune Purge Engine — AWS → Pulumi IaC Mapping (v2.3)

Pulumi (TypeScript, @pulumi/aws v7) resources for each AWS component of the v2.3 design, including per-tenant KMS and BYOK

Related: v2.3 design · review findings

Pulumi IaC Step Functions + Batch (Fargate) + SQS Least-Privilege Roles Per-Tenant KMS & BYOK
What changed for v2.3
  • Platform KMS key (aws.kms.Key) for DynamoDB, SQS, CloudWatch Logs, Step Functions and the manifests of PLATFORM_KEY tenants. SQS moves from SSE-SQS to this key.
  • Tenant-data role assumed with TenantId/TenantKmsKeyArn session tags. The job roles lose direct S3 access. The manifest bucket policy rejects untagged writers and writes with the wrong key.
  • Step Functions gets kms:DescribeKey and a conditioned kms:CreateGrant. The ASL adds the key preflight, skip states, the clone key check and the inaccessible-encryption-credentials branch.
  • Athena: a results bucket, one workgroup per TENANT_KEY tenant that enforces the tenant key, and a tenant-tagged audit role.
  • Batch: an explicit KMS-encrypted log group, exit code 78 for key loss (never retried), and the tenant-data role ARN passed in the environment.
  • Alarms: KeyMismatch, CloneStuckKeyUnavailable, and per tenant TenantKeyUnavailable and KeyMaterialHoursRemaining.
  • New section 3: the tenant key-policy statements, which live in the stack that owns the keys.

AWS → Pulumi IaC Mapping

Long-lived infrastructure is managed by Pulumi (TypeScript, @pulumi/aws v7). The ephemeral discovery clone is deliberately not a Pulumi resource. The Classic provider's aws.neptune.Cluster has no point-in-time or copy-on-write restore input (only snapshotIdentifier). Pulumi AWS Native (aws-native.neptune.DbCluster, which maps to AWS::Neptune::DBCluster) does expose restoreType, sourceDbClusterIdentifier and useLatestRestorableTime. Even so, a per-run clone doesn't belong in stack state, and you should never run pulumi up or pulumi destroy for each weekly run. Pulumi provisions everything the clone needs (IAM, subnet group, security group, parameter group). Step Functions creates and deletes the clone at runtime.

Tenant keys aren't owned by the purge stack. They belong to the stack that creates each tenant's dedicated cluster (a cluster's key is fixed at creation). That stack adds the purge statements to each key policy, using this stack's role ARNs through a StackReference (section 3). The purge stack never writes another stack's key policy: aws.kms.KeyPolicy replaces the whole policy.

IAM model
  • Control plane: Neptune management APIs (restore, create, delete, describe) are authorized with rds:* actions. Delete actions are limited to clone-named ARNs. v2.3: kms:DescribeKey for the preflight, and kms:CreateGrant only with kms:ViaService=rds.<region> and kms:GrantIsForAWSResource=true, which is what Neptune needs to restore an encrypted cluster. The tenant key policy must allow the same actions.
  • Discovery role: neptune-db:ReadDataViaQuery only, plus SQS/DynamoDB and the platform key via those services. It can only reach the clone because of the clone security group.
  • Executor role: ReadDataViaQuery, DeleteDataViaQuery and GetQueryStatus on the configured production resource IDs only. Graph deletes need no KMS permissions.
  • Tenant-data role (v2.3): all manifest reads and writes. The trust policy requires exactly the TenantId and TenantKmsKeyArn tags. Role chaining caps sessions at 1h, so containers use an auto-refreshing STS credentials provider. The tags stop cross-tenant bugs, not compromised code. A BYOK tenant that needs a hard boundary gets its own job definition and job role with the same policies and fixed values.

1. Pulumi Program (TypeScript, @pulumi/aws v7)

import * as pulumi from "@pulumi/pulumi";
import * as aws from "@pulumi/aws";
import * as fs from "fs";

const cfg = new pulumi.Config();
const vpcId = cfg.require("vpcId");
const privateSubnetIds = cfg.requireObject<string[]>("privateSubnetIds");          // same AZs as the source clusters
const prodClusterResourceIds = cfg.requireObject<string[]>("prodClusterResourceIds"); // cluster-XXXX
// v2.3: TENANT_KEY tenants (dedicated clusters). Keys are owned by the tenant onboarding stack (section 3).
const tenantKeyTenants = cfg.requireObject<{ tenantId: string; kmsKeyArn: string }[]>("tenantKeyTenants");
const auditPrincipalArns = cfg.requireObject<string[]>("auditPrincipalArns");      // who may run audit queries

const region = aws.getRegionOutput().name;
const accountId = aws.getCallerIdentityOutput().accountId;
const prefix = "neptune-purge";
// IAM policy variables. Plain strings, so TypeScript doesn't interpolate them.
const PT_TENANT = "${aws:PrincipalTag/TenantId}";
const PT_KEY = "${aws:PrincipalTag/TenantKmsKeyArn}";

// ---------- v2.3: platform KMS key (shared, non-customer-data stores) ----------
// Encrypts SQS, DynamoDB, CloudWatch Logs, Step Functions and manifests of PLATFORM_KEY tenants.
const platformKey = new aws.kms.Key("platform-key", {
    description: "Neptune purge platform key (no customer data)",
    enableKeyRotation: true,
    deletionWindowInDays: 30,
    policy: pulumi.all([region, accountId]).apply(([r, a]) => JSON.stringify({
        Version: "2012-10-17",
        Statement: [
            { Sid: "AccountAdmin", Effect: "Allow", Principal: { AWS: `arn:aws:iam::${a}:root` },
              Action: "kms:*", Resource: "*" },                       // IAM policies below grant use
            { Sid: "CloudWatchLogs", Effect: "Allow", Principal: { Service: `logs.${r}.amazonaws.com` },
              Action: ["kms:Encrypt*", "kms:Decrypt*", "kms:ReEncrypt*", "kms:GenerateDataKey*", "kms:Describe*"],
              Resource: "*",
              Condition: { ArnLike: { "kms:EncryptionContext:aws:logs:arn": `arn:aws:logs:${r}:${a}:log-group:*` } } },
        ],
    })),
});
new aws.kms.Alias("platform-key-alias", { name: `alias/${prefix}-platform`, targetKeyId: platformKey.keyId });

// Lets a role use the platform key only through the named services.
const platformKeyUse = (keyArn: string, r: string, services: string[]) => ({
    Effect: "Allow",
    Action: ["kms:Decrypt", "kms:GenerateDataKey", "kms:DescribeKey", "kms:CreateGrant"],
    Resource: keyArn,
    Condition: { StringEquals: { "kms:ViaService": services.map(s => `${s}.${r}.amazonaws.com`) } },
});

// ---------- DynamoDB: config, run ledger, chunk ledger, cluster leases (platform key) ----------
const table = (name: string, hashKey: string, rangeKey?: string, ttlAttr?: string) =>
    new aws.dynamodb.Table(name, {
        name,
        billingMode: "PAY_PER_REQUEST",
        hashKey,
        rangeKey,
        attributes: [{ name: hashKey, type: "S" }, ...(rangeKey ? [{ name: rangeKey, type: "S" }] : [])],
        pointInTimeRecovery: { enabled: true },
        serverSideEncryption: { enabled: true, kmsKeyArn: platformKey.arn },   // v2.3
        ttl: ttlAttr ? { attributeName: ttlAttr, enabled: true } : undefined,
    });
const tenantConfig = table("NeptuneTenantPurgeConfig", "TenantId");
const runLedger    = table("NeptunePurgeRunLedger", "TenantId", "RunId");
const chunkLedger  = table("NeptunePurgeChunkLedger", "RunKey", "ChunkId");
const clusterLease = table("NeptunePurgeClusterLease", "ClusterResourceId", undefined, "ExpiresAt");

// ---------- S3 manifest store (tenant-scoped encryption) ----------
const manifests = new aws.s3.Bucket("manifests", { bucketPrefix: `${prefix}-manifests-` });
new aws.s3.BucketPublicAccessBlock("manifests-pab", {
    bucket: manifests.id,
    blockPublicAcls: true, blockPublicPolicy: true, ignorePublicAcls: true, restrictPublicBuckets: true,
});
// The bucket default is only a fallback. Writers always send SSEKMSKeyId (tenant key or platform key).
new aws.s3.BucketServerSideEncryptionConfiguration("manifests-sse", {
    bucket: manifests.id,
    rules: [{ applyServerSideEncryptionByDefault: { sseAlgorithm: "aws:kms", kmsMasterKeyId: platformKey.arn },
              bucketKeyEnabled: true }],          // Bucket Keys work per KMS key, so they help per tenant too
});
new aws.s3.BucketLifecycleConfiguration("manifests-lc", {
    bucket: manifests.id,
    rules: [{ id: "expire-manifests", status: "Enabled", filter: {}, expiration: { days: 400 } }],
});
// v2.3: only tenant-tagged sessions may write, and only with the key named in their session tag.
new aws.s3.BucketPolicy("manifests-policy", {
    bucket: manifests.id,
    policy: manifests.arn.apply(b => JSON.stringify({
        Version: "2012-10-17",
        Statement: [
            { Sid: "DenyUntaggedWriters", Effect: "Deny", Principal: "*",
              Action: "s3:PutObject", Resource: `${b}/*`,
              Condition: { Null: { "aws:PrincipalTag/TenantId": "true" } } },
            { Sid: "DenyWrongKmsKey", Effect: "Deny", Principal: "*",
              Action: "s3:PutObject", Resource: `${b}/*`,
              Condition: { StringNotEquals: { "s3:x-amz-server-side-encryption-aws-kms-key-id": PT_KEY } } },
            { Sid: "DenyInsecureTransport", Effect: "Deny", Principal: "*",
              Action: "s3:*", Resource: [b, `${b}/*`],
              Condition: { Bool: { "aws:SecureTransport": "false" } } },
        ],
    })),
});

// ---------- SQS: edge phase, vertex phase, shared DLQ (pointers only, platform key) ----------
const FOURTEEN_DAYS = 1_209_600;               // default is 4 days; 14 days is the maximum
const dlq = new aws.sqs.Queue("chunk-dlq", {
    name: "NeptunePurgeChunkDLQ",
    messageRetentionSeconds: FOURTEEN_DAYS,    // >= source queues (expiry uses original enqueue time)
    kmsMasterKeyId: platformKey.arn,           // v2.3: was sqsManagedSseEnabled
    kmsDataKeyReusePeriodSeconds: 3600,
});
const phaseQueue = (phase: "edge" | "vertex") => new aws.sqs.Queue(`${phase}-queue`, {
    name: `NeptunePurge${phase === "edge" ? "Edge" : "Vertex"}Queue`,
    messageRetentionSeconds: FOURTEEN_DAYS,
    visibilityTimeoutSeconds: 900,             // heartbeat with ChangeMessageVisibility (max 12h from receipt)
    receiveWaitTimeSeconds: 20,
    kmsMasterKeyId: platformKey.arn,
    kmsDataKeyReusePeriodSeconds: 3600,
    redrivePolicy: dlq.arn.apply(arn => JSON.stringify({ deadLetterTargetArn: arn, maxReceiveCount: 3 })),
});
const edgeQueue = phaseQueue("edge");
const vertexQueue = phaseQueue("vertex");

const repo = new aws.ecr.Repository("purge-images", {

const assume = (svc: string) => JSON.stringify({
    Version: "2012-10-17",
    Statement: [{ Effect: "Allow", Principal: { Service: svc }, Action: "sts:AssumeRole" }],
});
const execRole = new aws.iam.Role("task-exec-role", { assumeRolePolicy: assume("ecs-tasks.amazonaws.com") });
new aws.iam.RolePolicyAttachment("task-exec-attach", {
    role: execRole.name,

const discoveryRole = new aws.iam.Role("discovery-role", { assumeRolePolicy: assume("ecs-tasks.amazonaws.com") });
const executorRole = new aws.iam.Role("executor-role", { assumeRolePolicy: assume("ecs-tasks.amazonaws.com") });

// v2.3: all S3 and tenant-key access goes through this role, assumed at container start with session tags
// TenantId and TenantKmsKeyArn (values come from job parameters set by Step Functions from TenantConfig).
// Tags guard against cross-tenant bugs, not compromised code (design 6.3).
const tenantScopedStatements = (b: string, r: string, a: string, pk: string) => [
    { Sid: "OwnPrefixOnly", Effect: "Allow", Action: ["s3:GetObject", "s3:PutObject"],
      Resource: `${b}/${PT_TENANT}/*` },
    { Sid: "ListOwnPrefix", Effect: "Allow", Action: "s3:ListBucket", Resource: b,
      Condition: { StringLike: { "s3:prefix": [`${PT_TENANT}/*`] } } },
    { Sid: "TenantKeyViaS3", Effect: "Allow", Action: ["kms:GenerateDataKey", "kms:Decrypt"],
      Resource: `arn:aws:kms:${r}:${a}:key/*`,
      Condition: { StringEquals: { "aws:ResourceTag/TenantId": PT_TENANT,
                                   "kms:ViaService": `s3.${r}.amazonaws.com` } } },
    { Sid: "PlatformKeyViaS3", Effect: "Allow", Action: ["kms:GenerateDataKey", "kms:Decrypt"],
      Resource: pk, Condition: { StringEquals: { "kms:ViaService": `s3.${r}.amazonaws.com` } } },
];
const tagTrust = (principals: pulumi.Input<string>[]) => pulumi.all([pulumi.all(principals), region, accountId])
    .apply(([p, r, a]) => JSON.stringify({
        Version: "2012-10-17",
        Statement: [{
            Effect: "Allow", Principal: { AWS: p }, Action: ["sts:AssumeRole", "sts:TagSession"],
            Condition: {
                StringLike: { "aws:RequestTag/TenantId": "?*",
                              "aws:RequestTag/TenantKmsKeyArn": `arn:aws:kms:${r}:${a}:key/*` },
                "ForAllValues:StringEquals": { "aws:TagKeys": ["TenantId", "TenantKmsKeyArn"] },
            },
        }],
    }));
const tenantDataRole = new aws.iam.Role("tenant-data-role", {
    name: `${prefix}-tenant-data`,
    // Role chaining (job role -> this role) caps sessions at 1h. Containers use an auto-refreshing
    // STS AssumeRole credentials provider with the same tags. They don't rely on maxSessionDuration.
    assumeRolePolicy: tagTrust([discoveryRole.arn, executorRole.arn]),
});
new aws.iam.RolePolicy("tenant-data-policy", {
    role: tenantDataRole.id,
    policy: pulumi.all([manifests.arn, region, accountId, platformKey.arn]).apply(([b, r, a, pk]) =>
        JSON.stringify({ Version: "2012-10-17", Statement: tenantScopedStatements(b, r, a, pk) })),
});

// Discovery: read-only graph access, no delete rights anywhere. No direct S3 access (v2.3).
new aws.iam.RolePolicy("discovery-policy", {
    role: discoveryRole.id,
    policy: pulumi.all([edgeQueue.arn, vertexQueue.arn, chunkLedger.arn, runLedger.arn, tenantDataRole.arn,
                        platformKey.arn, region, accountId])
        .apply(([eq, vq, cl, rl, td, pk, r, a]) => JSON.stringify({

                { Effect: "Allow", Action: ["sqs:SendMessage"], Resource: [eq, vq] },
                { Effect: "Allow", Action: ["dynamodb:PutItem", "dynamodb:UpdateItem", "dynamodb:GetItem"], Resource: [cl, rl] },

            ],

            Statement: [

3. Tenant Key Policy Statements (tenant onboarding stack)

The stack that owns each tenant's cluster and key adds these statements. It reads the purge role ARNs from this stack's outputs. Each tenant key must carry a TenantId tag, because the tenant-data role's IAM policy matches keys by aws:ResourceTag/TenantId. For BYOK, aws.kms.ExternalKey creates the key and imports the material. The purge preflight reads Origin, ExpirationModel and ValidTo from DescribeKey, so nothing BYOK-specific is stored in TenantConfig.

// Tenant onboarding stack (owns tenant clusters and keys). Not the purge stack.
import * as pulumi from "@pulumi/pulumi";
import * as aws from "@pulumi/aws";

const purge = new pulumi.StackReference("org/neptune-purge/prod");
const sfnRoleArn = purge.requireOutput("purgeSfnRoleArn");
const tenantDataRoleArn = purge.requireOutput("tenantDataRoleArn");
const tenantAuditRoleArn = purge.requireOutput("tenantAuditRoleArn");
const region = aws.getRegionOutput().name;
const accountId = aws.getCallerIdentityOutput().accountId;

// Statements every TENANT_KEY key policy must contain for the purge engine (design 6.3 (a)).
export const purgeKeyPolicyStatements = (tenantId: string) =>
    pulumi.all([sfnRoleArn, tenantDataRoleArn, tenantAuditRoleArn, region]).apply(([sfn, data, audit, r]) => [
        { Sid: "PurgeCloneGrant", Effect: "Allow", Principal: { AWS: sfn },
          Action: "kms:CreateGrant", Resource: "*",
          Condition: { StringEquals: { "kms:ViaService": `rds.${r}.amazonaws.com` },
                       Bool: { "kms:GrantIsForAWSResource": "true" } } },
        { Sid: "PurgePreflightDescribe", Effect: "Allow", Principal: { AWS: sfn },
          Action: "kms:DescribeKey", Resource: "*" },
        { Sid: "PurgeManifestCrypto", Effect: "Allow", Principal: { AWS: [data, audit] },
          Action: ["kms:GenerateDataKey", "kms:Decrypt"], Resource: "*",
          Condition: { StringEquals: { "kms:ViaService": `s3.${r}.amazonaws.com`,
                                       "aws:PrincipalTag/TenantId": tenantId } } },
    ]);

const keyPolicy = (tenantId: string) => pulumi.all([accountId, purgeKeyPolicyStatements(tenantId)])
    .apply(([a, purgeStatements]) => JSON.stringify({
        Version: "2012-10-17",

            { Sid: "AccountAdmin", Effect: "Allow", Principal: { AWS: `arn:aws:iam::${a}:root` },
              Action: "kms:*", Resource: "*" },
            // ... the tenant's own statements (Neptune service use, key administrators) ...
            ...purgeStatements,

// AWS-generated tenant key
const fin042 = new aws.kms.Key("tenant-eu-fin-042", {
