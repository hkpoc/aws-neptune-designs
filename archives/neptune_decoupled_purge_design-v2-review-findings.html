Part A — v2 vs. AWS Documentation (applied in v2.1)

Each statement in v2 was checked against the AWS documentation linked in the last column. Severity: High = would fail at build or run time; Medium = wrong value or misleading behavior; Low = imprecise wording or an unverified estimate.

1HighClone API RestoreDBClusterFromDBCluster with copy-tags-to-snapshot There is no such API. A Neptune clone is created with RestoreDBClusterToPointInTime using RestoreType=copy-on-write and UseLatestRestorableTime=true. CopyTagsToSnapshot has nothing to do with cloning. Pass Tags instead. Neptune DB cloning
2HighClone instance One restore call yields a usable clone endpoint. The restore call only creates the cluster, not its instances. Wait for the cluster to be available, call CreateDBInstance (db.r6g.* or db.serverless), then wait for the instance to be available. Step Functions has no .sync for Neptune, so you need explicit Wait + Describe* polling loops. RestoreDBClusterToPointInTime
3HighClone networking Not specified. The restored cluster gets the default DB security group unless you pass VpcSecurityGroupIds. Always pass VpcSecurityGroupIds, DBSubnetGroupName and DBClusterParameterGroupName. Otherwise the Fargate discovery task can't reach the clone, or the clone runs with default timeouts. RestoreDBClusterToPointInTime
4HighCloudWatch metric NumTxConflictErrors (CME) used as a throttle signal. No such Neptune metric exists. Track ConcurrentModificationException retries on the client as a custom EMF metric (ConcurrentModificationRetries). Use the Neptune NumTxRolledBack metric (writer) as a server-side proxy. Neptune CW metrics
5HighStep Functions "Native DynamoDB integration via Step Functions Distributed Map". The Distributed Map ItemReader reads only from S3 (CSV, JSON, JSONL, Parquet, Athena manifest, S3 inventory) or from JSON state input. Query TenantConfig with the aws-sdk:dynamodb:query task first, then fan out with a Map state (inline is enough for fewer than ~40 tenants). ItemReader (Map)
6MediumNCU logic Red if NCUs ≥ 85% of MaxNcu or NCUUtilization > 75%, treated as two separate signals. NCUUtilization is current NCUs ÷ the cluster's maximum NCU setting, so the two rules measure the same thing. The 85% rule could never fire because 75% fires first. Use NCUUtilization for headroom and ServerlessDatabaseCapacity (absolute NCUs) for the cost budget. Neptune CW metrics
7MediumMetric polling 30-second health polling loop. Neptune metrics are published at 1-minute intervals, so polling every 30s only returns duplicate datapoints. Poll every 60s. Neptune also only publishes non-zero values: treat a missing UndoLogListSize or MainRequestQueuePendingRequests datapoint as 0 (alarms: TreatMissingData=notBreaching). Neptune CW metrics
8MediumBuffer cache Green > 95%, Red < 85%. Cap batch size below 90%. AWS sets the healthy baseline at 99.9%. Below that, it advises adding memory. Thresholds tightened to Green ≥ 99%, Yellow 95–99%, Red < 95%. Metric best practices
9MediumSQS retention "SQS ... with a 14-day retention period" (implied default). 14 days is the maximum. The default is 4 days, so set MessageRetentionPeriod=1209600 explicitly. Give the DLQ a retention ≥ the source queue's, because standard-queue expiry is based on the original enqueue time. The visibility timeout maximum is 12h: heartbeat with ChangeMessageVisibility during circuit-breaker pauses. SQS FAQ · ChangeMessageVisibility
10MediumFargate Spot Discovery on Fargate Spot, "~70% savings". No interruption handling. The discount is "up to 70%". Spot tasks can be reclaimed with a 2-minute warning (SIGTERM). Discovery must checkpoint its cursor to the ledger and resume. Fargate Spot doesn't support ARM64: build the discovery image for x86_64. AWS HPC blog
11MediumOrphan reaper "fallback EventBridge rule ... force-deleted". An EventBridge rule can't delete resources by itself. Use an EventBridge Scheduler (hourly) that runs a reaper state machine: DescribeDBClusters → filter by tag Purpose=NeptunePurgeDiscovery and age > 4h → DeleteDBInstance → DeleteDBCluster(SkipFinalSnapshot=true). Neptune cloning
12LowClone timing & limits "~5–12 minutes regardless of storage". No clone limits stated. AWS doesn't publish a provisioning time. Treat any figure as an internal estimate and measure it. Documented limits: at most 15 clones per copy (including clones of clones), same Region only, no cross-account cloning. A clone always runs the latest patch of the source engine version. Neptune cloning
13LowUndoLog UndoLog thresholds stated without context. Only the writer purges the undo log, and records from deletes take longer to purge. Engine upgrades to ≥1.2.0.0 roll back if UndoLogListSize exceeds about 10k (smaller than 4xlarge) or 40k (4xlarge and larger). Don't schedule purges just before an engine upgrade. Neptune CW metrics
Statements verified as correct

Neptune Serverless range is 1.0–128.0 NCUs, set in half-step increments · 1 NCU = 2 GiB RAM plus matching vCPU and networking · ServerlessDatabaseCapacity, NCUUtilization, BufferCacheHitRatio, MainRequestQueuePendingRequests, UndoLogListSize and CPUUtilization all exist · a clone uses copy-on-write and needs no extra storage at creation · Step Functions batch:submitJob.sync waits for job completion · SQS retention can go up to 14 days · Lambda has a 15-minute cap · ConcurrentModificationException is the Neptune write-conflict error, retried with exponential backoff.

Part B — Cross-Check with the v3b Review (applied in v2.2)

An independent review (neptune_decoupled_purge_design-v3b.html) was compared with Part A. The rows below are the gaps it surfaced, plus two internal inconsistencies found during the comparison (#16, #27). AWS-documented facts were re-verified where cited.

#Sev.AreaIssue in v2.1Change in v2.2Source
14HighLive-data correctness Deletes use clone IDs as authority (g.E(ids).drop()). A record renewed, relabeled or reassigned after the snapshot would still be deleted. Each production delete re-applies the tenant, label and frozen-cutoff predicates in the same query. Outcomes are classified as Deleted, AlreadyAbsent, NoLongerEligible or Uncertain (design 5.4). v3b · cloning (point-in-time)
15HighClone security Restore didn't set IAM auth. The discovery job role had neptune-db:* on *. EnableIAMDatabaseAuthentication defaults to false on restore, so pass true. Discovery gets ReadDataViaQuery only. The executor gets Read, Delete and GetQueryStatus scoped to production cluster resource IDs. RestoreDBClusterToPointInTime · data-plane IAM
16HighClone reaper The reaper deleted tagged clones older than 4h, but the discovery job timeout is 6h, so it could delete a clone mid-scan. The reaper requires ownership tags, a non-running owner execution or an expired lease heartbeat, and a clone-pattern ID. Age alone is never sufficient. The Step Functions role can only delete neptune-clone-* ARNs. Internal consistency
17HighWriter failover Config stored a static WriterInstanceIdentifier. After a failover, health metrics would come from a reader. Resolve the current writer every cycle from DBClusterMembers[IsClusterWriter]. A writer change is Red: reconnect and re-baseline. CW metrics (instance dimension)
18HighShared clusters Throttle state lived in each tenant job, so N tenants on one cluster meant N times the load. Use one controller and rate budget per source cluster, coordinated through a NeptunePurgeClusterLease item with a fencing token and heartbeat. v3b
19HighVertex semantics "Edges first" was enforced only by ordering, and vertex drops didn't account for incident edges. Dropping a vertex removes all its edges, so add a per-rule VertexEdgePolicy (for example ORPHAN_ONLY → .not(bothE())). The vertex phase starts only after every edge chunk is terminal in the chunk ledger. v3b
20MediumTenant scope Discovery assumed one tenant per cluster. A clone contains the whole source cluster, so filter on TenantIdProperty in every discovery and delete query when clusters are shared. v3b
21MediumAccounting Counts were incremented per chunk with UpdateItem ADD. SQS delivers at least once, and drop() returns no counts. Add a chunk ledger with conditional claims and fencing. TransactWriteItems completes the chunk and updates run totals once. A crash between the graph commit and the ledger commit is resolved as UNCERTAIN by re-reading. v3b · SQS at-least-once
22MediumManifest lifecycle SQS pointers were published as chunks were written. A window that closed early still reported COMPLETED. Seal the manifest only after the full scan, then publish pointers. An executor never starts on an unsealed manifest. A run that hits its window ends PAUSED and is resumed before the next discovery. v3b
23MediumRetention rule SESSION_EVENT used RetentionDays: 90 on expiresAtEpoch, which already holds an expiry time, so retention was counted twice. CutoffMode: BEFORE_RUN_CUTOFF for expiry properties. RETENTION_DAYS (cutoff = run start − N days, applied once) for creation timestamps. v3b
24MediumClone preflight No check that the source cluster is restorable. Before restoring, require Status=available and a non-null LatestRestorableTime. Never fall back to a full copy, which is the default when RestoreType is omitted. RestoreDBClusterToPointInTime
25MediumThrottle signals Only CloudWatch, at 1-minute resolution. Add the live query queue (acceptedQueryCount − runningQueryCount via GetQueryStatus, every 15s) and the application's p95 latency against its SLO. Adjust a single rate rather than batch size, workers and delay together. A missing CPUUtilization datapoint (always published) means stale → Red. Gremlin status API
26LowChunk math 1,186 chunks, which assumed edges and vertices were mixed in chunks. Edges and vertices are chunked separately for the phase barrier: 965 + 222 = 1,187. Arithmetic
27LowSFN parameter casing ASL mixed SourceDBClusterIdentifier with DbClusterIdentifier. Use the SDK casing consistently (SourceDbClusterIdentifier, DbSubnetGroupName, EnableIamDatabaseAuthentication). Validate with validate-state-machine-definition. SFN SDK integrations
